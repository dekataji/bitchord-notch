# BitChord Notch

A portable, single-binary Windows companion for a BitChord phone
running the web remote control. It floats at the top-centre of the
screen like a notch:

- **Collapsed** — a slim pill: prev / play-pause / next, song title,
  artist, elapsed time.
- **Expanded** — tabs for **Queue** (play, reorder, remove),
  **Lyrics** (synced lyrics that follow the song; double-click a line
  to seek there) and **Settings**, plus a seek bar and
  shuffle / repeat / volume controls.

It talks to the phone through the VPS relay
(`https://remote.gaspol.men/r/<token>/...`) exactly like the browser
player, or directly over the LAN (`http://<phone-ip>:8899`) when no
relay token is set.

## Use

1. Copy `BitChordNotch.exe` anywhere and run it. No install, no
   runtime — one 10 MB file. Settings are stored in
   `bitchord-notch.json` next to the exe.
2. First run opens the Settings tab:
   - **Relay URL:** `https://remote.gaspol.men`
     (or the phone's `http://192.168.x.x:8899` for LAN mode)
   - **Relay token:** the token from BitChord's relay setup
     (leave blank in LAN mode)
   - **Remote PIN:** the PIN set in BitChord → Settings → Remote control
   - **Your name:** label shown in the phone's remote user list
3. Make sure the remote is started on the phone and the phone is
   connected to the relay.

Drag the notch by its title area. It lives in the system tray —
left-click the tray icon to show/hide, right-click for the menu;
closing the window hides it to the tray, Exit is in the tray menu.

## Build

```sh
./build.sh        # cross-compiles dist/BitChordNotch.exe from Linux
go test ./client/ # protocol tests (stub phone + relay prefix)
```

`rsrc.syso` (icon + manifest) is generated by `gen_assets.py` and the
`rsrc` tool, and committed so builds are reproducible.

## Layout

- `client/` — the remote API client (unlock/session, state, commands,
  lyrics) + config persistence. Platform-neutral and unit-tested.
- `main.go`, `pages.go`, `widgets.go` — the notch UI (walk / Win32).
- `third_party/walk` — a vendored copy of lxn/walk with three
  nil-guards in `mainwindow.go`: under Wine, a WM_SIZE arrives while
  the window is still being created, before `statusBar`/`menu` exist,
  and stock walk dereferences them and crashes. The guards are
  no-ops on native Windows.
- `test/stub_phone.py` — a stub of the phone API used to test the
  real exe end-to-end under Wine (Xvfb + xdotool) on a headless box.

Two walk lessons baked into the code (both bit v0.1.0 in the field):
buttons are native `PushButton`s because `MouseDown` handlers on
label/composite pairs never fired, and list boxes are fed plain
`[]string` models because a hand-rolled model that only implements
`ItemCount`/`Value` silently yields an empty list (walk's
`ListModel` also requires the change-event methods).

Debug logging: drop an empty `debug.on` file next to the exe and the
app writes `bitchord-notch.log` (button clicks, command failures).
